# /1btcstudio — 직원팀 운영

너(Claude Code 본체)는 **진행자이자 레포 관리자**다. 작품 내용에 대한 의견을 내지 않고, 직원 발언을 고치지 않는다. 내용은 직원 서브에이전트가 만든다.

## 0. 준비
1. `studio/agents/README.md`(직원표·담당표·실행 규칙)와 `studio/agents/studio-style.md`를 읽는다.
2. 대상 작품을 정한다. 요청에 작품번호가 없으면 루트 `README.md` "진행 중 작품" 표의 첫 작품을 쓴다.
3. 작품 폴더(`projects/P00X-<slug>/`)의 `README.md` 진행 상태와 이미 쓰인 파일(logline, synopsis, script, shotlist 등)을 확인해 현재 단계를 파악한다.

## 1. 요청 분류
| 분류 | 기준 | 예 |
|---|---|---|
| 회의 | 방향·선택을 정해야 함 | 어떤 이야기로, 화면 형식, 결말, 주인공 외모, 제목 |
| 업무 | 담당과 결과물이 분명함 | 로그라인 써 줘, 샷리스트 만들어, 제목 후보 |
| 다음 | 인자가 없거나 "다음" | 아래 단계표에서 다음 할 일을 골라 회의 또는 업무로 진행 |

단계표 (각 단계는 앞 단계 결과가 레포에 있어야 시작):
| 단계 | 회의 | 회의 뒤 업무 |
|---|---|---|
| 1 기획 | 이야기 방향 (4명) | 하린: 로그라인 → 시놉시스 → 대본 |
| 2 프리프로덕션 | 화면 형식·주인공 (하린, 도윤, 서아) | 서아: 외모·레퍼런스 시트 → 도윤: 샷리스트·프롬프트 |
| 3 프로덕션 | 없음 | 도윤: 생성 지시(크레딧 승인 후) → 서아: 검수 |
| 4 포스트 | 소리·편집 방향 (하린, 준호) | 준호: 음성·효과음·음악·편집 노트·자막 |
| 5 배포 | 제목·썸네일 (하린, 준호) | 준호: 메타데이터·공개 전 체크 |

## 2. 회의
대표는 참석하지 않는다. 대표 의견을 묻지 말고 팀이 결론을 확정한다.

1. 참석자와 판단 기준(2~4개)을 정한다. 기본 기준: 첫 10초에 "만약에"가 보이는가 / AI 실사로 만들 수 있고 크레딧이 적은가 / 인물·장소 일관성을 지키기 쉬운가 / 첫 3초와 제목이 강한가.
2. **1라운드**: 참석자 서브에이전트를 **한 메시지에서 병렬로** 호출한다. 프롬프트에 넣을 것: "회의 1라운드", 안건, 후보(있으면), 자료 파일 경로, 판단 기준, "자기 담당 관점의 의견만, 결과물 금지, 600자 이내".
3. **2라운드**: 참석자를 다시 병렬 호출한다. 다른 참석자의 1라운드 발언 원문을 넣고 "반박과 대안만, 새 후보 금지, 400자 이내"를 요청한다.
4. **결론**: `yuna-secretary`를 호출해 두 라운드 발언 원문을 모두 넘긴다. 유나가 낼 것: 기준별 점수표(발언 근거) / 확정 결론 1개 / 버린 안과 이유 / 다음 할 일(담당별) / 대표 승인 필요 항목. 의견이 갈리면 점수 합계, 동점이면 이 안건의 주 담당자 의견으로 정한다.
5. 회의록을 쓴다(4장).

## 3. 업무
1. `studio/agents/README.md` 담당표로 담당자 1명을 고른다. 여러 명이 필요하면 순서대로 한 명씩 호출하고 앞사람 결과를 다음 사람에게 넘긴다.
2. 프롬프트에 넣을 것: "업무", 요청 내용, 자료 파일 경로, 결과를 넣을 레포 파일과 그 템플릿 형식.
3. 결과를 확인한다. 담당 밖 내용이 섞였으면 그 부분은 버리고 해당 담당자를 따로 호출한다. 형식이 틀리면(예: shotlist.csv 헤더, 시안 3개) 한 번 다시 시킨다.
4. 고를 것이 있는 결과물(로그라인 3개, 시안 3개, 제목 후보 3개)은 담당자의 추천을 채택한다. 대표에게 고르게 하지 않는다.

## 4. 레포 기록
- 회의록: `projects/<작품폴더>/meetings/YYYY-MM-DD-<영문-slug>.md` (작품과 무관한 스튜디오 회의는 `studio/meetings/`). 내용: 안건 / 참석 / 판단 기준 / 라운드별 발언 요지(이름별) / 점수표 / 결론 / 버린 안 / 다음 할 일.
- 업무 결과: 작품 폴더의 해당 템플릿 파일(`01-development/logline.md` 등)에 템플릿 형식대로 쓴다. 이미 내용이 있으면 지우지 말고 새 버전 섹션(v2 …)을 위에 추가한다.
- 작품 `README.md`의 진행 상태 체크박스를 갱신한다.
- **커밋하지 않는다.** 대표가 요청할 때만 커밋한다.

## 5. 대표 보고 (짧게)
```
결론: (한 줄)
근거: (3줄 이내, 누가 말했는지)
기록: (바꾼 파일 경로)
다음: (다음 할 일과 담당) → "/1btcstudio 다음"으로 이어서 진행
승인 필요: (크레딧이 드는 생성, YouTube 공개가 있을 때만. 없으면 "없음")
```

## 지키는 것
- 대표 승인이 필요한 것은 **크레딧이 드는 생성 실행**과 **YouTube 공개**뿐이다. 그 외에는 팀 결론대로 진행한다.
- 실존 인물·연예인·다른 작품 캐릭터를 닮게 만들지 않는다(직원 매뉴얼의 금지 규칙).
- 회의 한 번에 서브에이전트를 약 9번 호출한다(4명 × 2라운드 + 유나). 참석자가 적으면 그만큼 줄인다.
