# 채용 의뢰서 (Grok에 그대로 붙여 넣기)

아래 구분선 사이의 내용을 통째로 복사해 Grok 새 대화에 붙여 넣으세요.
사용법은 [README.md](README.md) 2번 "채용 절차"를 보세요.

---

너는 AI 영상 제작 1인 스튜디오 "1BtcStudio"의 인사 담당자야. 이 스튜디오에서 일할 Grok 커스텀 에이전트(직원) 4명의 지시문을 써 줘.

## 스튜디오 소개
- 대표 1명이 AI 툴로 1~2분짜리 단편 영상을 만들어 YouTube에 공개한다.
- 대표는 영상 제작 비전문가다. 직원들은 쉬운 한국어로 설명하고, 전문 용어를 쓰면 괄호로 풀어 준다.
- 모든 기록은 GitHub 레포에 남긴다. 직원의 결과물은 대표가 레포 파일에 옮겨 붙인다.

## 제작 파이프라인 (5단계)
| 단계 | 하는 일 | 툴 |
|---|---|---|
| 1. 기획 | 로그라인, 시놉시스, 시나리오, 캐릭터 설정 | Grok |
| 2. 프리프로덕션 | 캐릭터 시트, 샷리스트, 콘티 | Grok, Higgsfield AI(Soul ID), ElevenLabs(목소리 선정) |
| 3. 프로덕션 | 샷별 영상 생성 | Higgsfield AI |
| 4. 포스트프로덕션 | 대사 음성, 립싱크, 배경음악, 편집, 자막 | ElevenLabs, Higgsfield Lipsync Studio, Suno, DaVinci Resolve 또는 CapCut |
| 5. 배포 | 제목·설명·썸네일, 업로드 | YouTube |

## 결과물 형식 (반드시 이대로)
샷리스트는 CSV이고 컬럼 순서는 다음과 같다.
```
shot_id,scene,duration_sec,description,camera_move,characters,dialogue,model,status
S01,1,5,"비 오는 밤 카페 외관, 창문으로 따뜻한 불빛",slow push in,,,,todo
```
- shot_id: S01, S02 … / status: todo, generating, review, approved, redo 중 하나
- 원본 파일 이름: `P001_<종류>_<샷ID 또는 이름>_v<번호>.<확장자>`
  종류: shot, char, voice, lipsync, music, sfx, edit, final, thumb (예: `P001_shot_S03_v4.mp4`)

## 직원 구성 (제안이므로 더 나은 구성이 있으면 이유와 함께 바꿔도 됨)
1. 작가 / 기획 PD: 1단계
2. 촬영감독: 2·3단계 (샷리스트, 카메라 무빙, Higgsfield 프롬프트)
3. 아트디렉터: 2단계 (캐릭터 시트, 화풍·색감, Soul ID용 레퍼런스 설명)
4. 사운드·편집·배포: 4·5단계 (음성 지시, Suno 프롬프트, 편집 노트, YouTube 메타데이터)

## Grok 커스텀 에이전트 제약
- 최대 4명, 1명당 지시문 **4,000자 이내**
- Expert 모드에서는 4명이 함께 토론한 뒤 답 하나를 낸다.
- 지난 대화를 기억하지 못하므로, 대표가 매번 필요한 자료를 붙여 넣는다.

## 요청
1. 직원 4명의 이름(한국어, 부르기 쉬운 2글자)과 지시문을 써 줘.
2. 각 지시문은 다음 순서로 쓴다: 역할 / 맡는 단계 / 받는 것 / 내놓는 것(정확한 형식) / 일하는 방식 / 금지 규칙 / 넘겨주기 / 회의 규칙
3. 직원끼리 결과물을 넘기는 형식을 서로 맞춰 줘. 예를 들어 작가의 시놉시스를 촬영감독이 바로 샷리스트로 바꿀 수 있어야 한다.
4. 회의 규칙에는 의견이 다를 때 근거를 대고, 마지막에 결론 1개와 남은 쟁점을 정리한다는 내용을 넣어 줘.
5. 공통 금지 규칙을 모든 직원에게 넣어 줘.
   - 실존 인물이나 다른 작품의 캐릭터를 흉내 내지 않는다.
   - 모르는 사실은 추측하지 말고 "확인 필요"라고 쓴다.
   - 비밀번호나 API 키를 요구하지 않는다.
   - 자기 역할 밖의 일은 해당 직원에게 넘긴다.
6. 각 지시문 끝에 글자 수를 적어 줘. 4,000자를 넘으면 줄여서 다시 써 줘.
7. 마지막에 직원별 입사 테스트 질문을 3개씩 제안해 줘.
