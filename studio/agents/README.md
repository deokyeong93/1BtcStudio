# Grok 직원 채용 가이드북

1BtcStudio에서는 Grok 에이전트를 **직원**으로 씁니다. 이 문서는 직원을 뽑고(등록) 일을 맡기는 방법을 설명합니다.

> 아래 Grok 기능 설명은 2026년 3월 출시 기준으로 정리한 것입니다. 메뉴 이름이나 제한은 바뀔 수 있으니, 처음 세팅할 때 **실제 화면과 공식 안내를 한 번 확인**하고 달라진 점이 있으면 이 문서를 고쳐 주세요.

## 1. 개념 — 스튜디오에 빗대면

| Grok 용어 | 스튜디오에 빗대면 | 설명 |
|---|---|---|
| 커스텀 에이전트 | 직원 | 이름과 역할이 정해진 Grok. **최대 4명**까지 둘 수 있습니다. |
| 지시문 (Instructions) | 업무 매뉴얼 | 직원이 어떻게 일할지 적은 글. **1명당 4,000자 이내**로 씁니다. |
| Expert 모드 | 회의 | 4명이 동시에 투입되어 서로 의견을 나눈 뒤 답 하나를 정리해 줍니다. "직원들끼리 상호작용"이 바로 이것입니다. |
| 이름 부르기 | 업무 지시 | 메시지 첫머리에 이름을 쓰면(`민준, 로그라인 3개 써 줘`, 이름은 예시) 그 직원이 맡습니다. 부르지 않으면 Grok이 알아서 배정합니다. |

알아 둘 한계
- 직원은 **지난 대화를 기억하지 못합니다.** 일을 맡길 때마다 필요한 문서(시놉시스, 샷리스트 등)를 붙여 넣어야 합니다.
- 대화가 길어지면(약 20번 주고받은 뒤) 지시문을 덜 지키는 경향이 있습니다. 그때는 **새 대화**를 여세요.
- 4명이 회의를 해도 결국 AI입니다. 사실 정보, 저작권, 상업 이용 조건은 **사람이 직접 확인**합니다.

## 2. 채용 절차

GitHub 이슈 `[툴 세팅] Grok`을 진행하면서 함께 하면 됩니다.

1. **채용 의뢰** — [hiring-brief.md](hiring-brief.md)의 내용을 통째로 복사해 Grok 새 대화(일반 모드)에 붙여 넣습니다. Grok이 직원 4명의 지시문 초안을 써 줍니다.
2. **검토** — 아래 3번 "지시문 틀"의 항목이 다 들어 있는지, 4,000자를 넘지 않는지 봅니다. 마음에 안 드는 부분은 "촬영감독 지시문에서 ○○를 빼고 다시 써 줘"처럼 고쳐 달라고 합니다.
3. **등록** — grok.com → 왼쪽 아래 프로필 → **Settings** → **Customize** → **Create Agent**. 이름과 지시문을 붙여 넣고 저장합니다. 4명 모두 반복합니다.
4. **입사 테스트** — 직원마다 질문 5개 정도를 던져 봅니다(아래 예시). 역할에 맞게 답하는지, 금지 규칙을 지키는지 확인합니다.
5. **원본 보관** — 확정된 지시문을 레포에 `studio/agents/<역할>.md`로 저장하고 커밋합니다(예: `writer.md`, `dp.md`). Grok 안에만 두면 바뀐 이력이 남지 않습니다.
6. **기록** — 루트 `CHANGELOG.md` "추가"에 직원 등록을 적고, `studio/tools.md` Grok 메모를 채웁니다.

입사 테스트 질문 예시
- "자기소개와 네가 맡는 일, 맡지 않는 일을 말해 줘."
- (작가) "비 오는 카페를 배경으로 1분짜리 단편 로그라인 3개."
- (촬영감독) "이 시놉시스로 샷리스트 5줄을 shotlist.csv 형식으로."
- (금지 규칙 확인) 일부러 역할 밖의 일을 시켜 보고, 다른 직원에게 넘기는지 확인

## 3. 지시문 틀

직원 1명의 지시문은 아래 항목으로 구성합니다. 레포에 저장하는 `studio/agents/<역할>.md`도 이 순서를 따릅니다.

```
# 이름 — 직책
## 역할        한 문장으로. 무엇을 책임지는가
## 맡는 단계   1 기획 / 2 프리프로덕션 / 3 프로덕션 / 4 포스트 / 5 배포 중
## 받는 것     누구에게서 어떤 자료를 받아 일하는가
## 내놓는 것   결과물과 정확한 형식 (예: shotlist.csv 컬럼 그대로)
## 일하는 방식 말투, 질문 규칙(모르면 추측하지 말고 묻기 등)
## 금지 규칙   "~하지 않는다" 형태로. 핵심은 두 번 반복
## 넘겨주기    다음 직원에게 무엇을, 어떤 형식으로 넘기는가
## 회의 규칙   Expert 모드에서 다른 직원과 의견이 다를 때의 태도
```

잘 쓰는 요령
- 금지 규칙은 "~하지 마" 형태가 잘 지켜집니다. (예: "이모지를 쓰지 않는다")
- 출력 형식은 예시 한 줄을 직접 보여 주는 것이 가장 확실합니다.
- 4,000자를 넘으면 스튜디오 공통 설명(파이프라인, 툴 목록)부터 줄이세요. 공통 설명은 일 맡길 때 붙여 넣어도 됩니다.

## 4. 직원 구성 제안 (확정 아님)

슬롯이 4개뿐이라 5단계를 4명이 나눠 맡습니다. 채용 의뢰 결과를 보고 바꿔도 됩니다.

| 직책 | 맡는 단계 | 하는 일 | 결과물이 들어갈 곳 |
|---|---|---|---|
| 작가 / 기획 PD | 1 | 로그라인, 시놉시스, 시나리오, 캐릭터 설정 | `01-development/` |
| 촬영감독 (DP) | 2·3 | 샷리스트, 카메라 무빙, Higgsfield 프롬프트 | `02-preproduction/shotlist.csv`, `03-production/prompts/` |
| 아트디렉터 | 2 | 캐릭터 시트, 화풍·색감 가이드, Soul ID용 레퍼런스 설명 | `02-preproduction/character-sheets/`, `storyboard.md` |
| 사운드·편집·배포 | 4·5 | 대사 음성 지시, Suno 음악 프롬프트, 편집 노트, YouTube 제목·설명 | `04-post/`, `05-distribution/youtube.md` |

## 5. 일 맡기는 법

- **혼자 할 일**: 이름을 불러 맡깁니다. `서연, 아래 시놉시스로 캐릭터 시트 설명 써 줘` + 시놉시스 붙여 넣기
- **같이 정할 일**: Expert 모드로 바꾸고 회의 안건을 줍니다. `회의: P001 결말을 A/B 중 무엇으로 할지. 각자 의견과 이유를 말하고 하나로 정리해 줘`
- **결과물 옮기기**: 직원이 준 결과는 그대로 두지 말고 레포의 해당 파일(위 표)에 붙여 넣고 커밋합니다. 레포가 정본이고, Grok 대화는 초안입니다.
- **생성 기록**: Higgsfield 등 생성 툴에 프롬프트를 넣었다면 `03-production/generation-log.md`에 기록합니다(작성은 직원, 기록은 사람).

## 6. 지시문 고치는 규칙

1. 레포의 `studio/agents/<역할>.md`를 먼저 고칩니다.
2. Grok **Customize** 화면에서 해당 직원 지시문에 그대로 붙여 넣습니다.
3. 루트 `CHANGELOG.md` "변경"에 한 줄 적습니다. 바꾼 *이유*가 중요하면 `studio/decisions/`에 결정 문서를 씁니다.

## 7. 주의

- 비밀번호, API 키, 결제 정보는 **Grok 대화에 절대 붙여 넣지 않습니다.**
- 실존 인물의 얼굴·목소리·이름, 다른 작품의 캐릭터를 흉내 내라고 시키지 않습니다. 상업 이용 조건은 `studio/licenses.md`를 따릅니다.
