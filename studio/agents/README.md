# Grok 직원 채용 가이드북

1BtcStudio에서는 Grok 에이전트를 **직원**으로 씁니다. 이 문서는 직원을 뽑고(등록) 일을 맡기는 방법을 설명합니다.

> 아래 Grok 기능 설명은 2026년 3월 출시 기준으로 정리한 것입니다. 메뉴 이름이나 제한은 바뀔 수 있으니, 처음 세팅할 때 **실제 화면과 공식 안내를 한 번 확인**하고 달라진 점이 있으면 이 문서를 고쳐 주세요.

## 1. 개념 — 스튜디오에 빗대면

| Grok 용어 | 스튜디오에 빗대면 | 설명 |
|---|---|---|
| 커스텀 에이전트 | 직원 | 이름과 역할이 정해진 Grok. **최대 4명**까지 둘 수 있습니다. |
| 지시문 (Instructions) | 업무 매뉴얼 | 직원이 어떻게 일할지 적은 글. **1명당 4,000자 이내**로 씁니다. |
| Expert 모드 | 회의 | 4명이 동시에 투입되어 서로 의견을 나눈 뒤 답 하나를 정리해 줍니다. "직원들끼리 상호작용"이 바로 이것입니다. |
| 이름 부르기 | 업무 지시 | 메시지 첫머리에 이름을 쓰면(`하린, 로그라인 3개 써 줘`) 그 직원이 맡습니다. 부르지 않으면 Grok이 알아서 배정합니다. |

알아 둘 한계
- 직원은 **지난 대화를 기억하지 못합니다.** 일을 맡길 때마다 필요한 문서(시놉시스, 샷리스트 등)를 붙여 넣어야 합니다.
- 대화가 길어지면(약 20번 주고받은 뒤) 지시문을 덜 지키는 경향이 있습니다. 그때는 **새 대화**를 여세요.
- 4명이 회의를 해도 결국 AI입니다. 사실 정보, 저작권, 상업 이용 조건은 **사람이 직접 확인**합니다.

## 2. 채용 절차

GitHub 이슈 `[툴 세팅] Grok`을 진행하면서 함께 하면 됩니다.

### 먼저 실제 화면에서 확인할 것
이 문서의 Grok 기능 설명은 웹 기사 기준입니다. 등록 전에 아래를 확인하고, 다르면 오른쪽 대안대로 진행한 뒤 이 문서를 고쳐 주세요.

| 확인할 것 | 기대값 | 다를 때 대안 |
|---|---|---|
| 메뉴 경로 | Settings → Customize → Create Agent | 설정 화면에서 "Agents", "Customize" 메뉴를 찾아봅니다 |
| 만들 수 있는 직원 수 | 4명 | 3명 이하면 서아(아트디렉터) 업무를 도윤(촬영감독)에게 합칩니다 |
| 지시문 글자 제한 | 4,000자 | 더 짧으면 지시문의 [스튜디오] 블록을 빼고, 일 맡길 때 첫 메시지에 붙여 넣습니다 |
| Expert 모드에서 커스텀 직원이 쓰이는지 | 4명이 함께 답함 | 안 되면 회의 대신 직원을 한 명씩 차례로 불러 의견을 모읍니다 |
| 메모리(지난 대화 기억) 기능 | 켜져 있을 수 있음 | 작품끼리 설정이 섞이지 않도록 **새 작품을 시작할 때는 새 대화**를 엽니다 |

1. **지시문 초안** — 4명의 초안이 이미 있습니다: [writer.md](writer.md), [dp.md](dp.md), [art.md](art.md), [post.md](post.md). 대표와 면담해 정한 [studio-style.md](studio-style.md)를 근거로 썼습니다.
2. **검토** — 초안을 읽고 마음에 안 드는 부분을 고칩니다. 방향 자체가 바뀌면 `studio-style.md`부터 고칩니다. 이름(하린·도윤·서아·준호)도 바꿔도 됩니다(4개 파일의 [스튜디오] 동료 목록도 함께).
3. **등록** — grok.com → 왼쪽 아래 프로필 → **Settings** → **Customize** → **Create Agent**. 이름과 지시문을 붙여 넣고 저장합니다. 4명 모두 반복합니다.
4. **입사 테스트** — 직원마다 질문 5개 정도를 던져 봅니다(아래 예시). 역할에 맞게 답하는지, 금지 규칙을 지키는지 확인합니다.
5. **원본 보관** — 테스트하며 고친 내용은 `studio/agents/<역할>.md`에 반영하고 커밋합니다. 머리말의 상태를 "초안" → "등록됨"으로 바꿉니다. Grok 안에만 두면 바뀐 이력이 남지 않습니다.
6. **기록** — 루트 `CHANGELOG.md` "추가"에 직원 등록을 적고, `studio/tools.md` Grok 메모를 채웁니다.

입사 테스트 질문은 각 지시문 파일 끝에 있습니다. 공통 예시:
- "자기소개와 네가 맡는 일, 맡지 않는 일을 말해 줘."
- (작가) "비 오는 카페를 배경으로 1분짜리 단편 로그라인 3개."
- (촬영감독) "이 시놉시스로 샷리스트 5줄을 shotlist.csv 형식으로."
- (금지 규칙 확인) 일부러 역할 밖의 일을 시켜 보고, 다른 직원에게 넘기는지 확인
- (회의 확인) 4명 등록 후 Expert 모드에서 위 회의 양식으로 짧은 안건을 줘 보고, 발언마다 [이름]이 붙고 각자 담당만 말하는지 확인

## 3. 지시문 틀

직원 1명의 지시문은 아래 항목으로 구성합니다. 레포에 저장하는 `studio/agents/<역할>.md`도 이 순서를 따릅니다.

```
# 이름 — 직책
## 역할        한 문장으로. 무엇을 책임지는가
## 맡는 단계   1 기획 / 2 프리프로덕션 / 3 프로덕션 / 4 포스트 / 5 배포 중
## 받는 것     누구에게서 어떤 자료를 받아 일하는가
## 내놓는 것   결과물과 정확한 형식 (예: shotlist.csv 컬럼 그대로)
## 일하는 방식 말투, 질문 규칙(모르면 추측하지 말고 묻기 등)
## 금지 규칙   "~하지 않는다" 형태로. 핵심은 두 번 반복
## 넘겨주기    다음 직원에게 무엇을, 어떤 형식으로 넘기는가
## 회의 규칙   Expert 모드에서 다른 직원과 의견이 다를 때의 태도
```

잘 쓰는 요령
- 금지 규칙은 "~하지 마" 형태가 잘 지켜집니다. (예: "이모지를 쓰지 않는다")
- 출력 형식은 예시 한 줄을 직접 보여 주는 것이 가장 확실합니다.
- 4,000자를 넘으면 스튜디오 공통 설명(파이프라인, 툴 목록)부터 줄이세요. 공통 설명은 일 맡길 때 붙여 넣어도 됩니다.

## 4. 직원 구성

슬롯이 4개뿐이라 5단계를 4명이 나눠 맡습니다. 각자의 스타일은 [studio-style.md](studio-style.md)에 있습니다.

| 이름 | 직책 | 맡는 단계 | 하는 일 | 결과물이 들어갈 곳 | 지시문 |
|---|---|---|---|---|---|
| 하린 | 작가 / 기획 PD | 1 | 로그라인, 시장성 판단, 시놉시스, 대본, 캐릭터 설정, 세계관 | `01-development/` | [writer.md](writer.md) |
| 도윤 | 촬영감독 | 2·3 | 샷리스트, Higgsfield 프롬프트, 재생성 지시 | `02-preproduction/shotlist.csv`, `03-production/prompts/` | [dp.md](dp.md) |
| 서아 | 아트디렉터 | 2·3 | 외모 시안, 캐릭터·레퍼런스 시트, 샷 검수 | `02-preproduction/character-sheets/` | [art.md](art.md) |
| 준호 | 사운드·편집·배포 | 4·5 | 음성·효과음·음악 지시, 편집 노트, YouTube 메타데이터 | `04-post/`, `05-distribution/youtube.md` | [post.md](post.md) |

## 5. 일 맡기는 법

- **혼자 할 일**: 이름을 불러 맡깁니다. `서아, 아래 시놉시스로 캐릭터 시트 설명 써 줘` + 시놉시스 붙여 넣기
- **같이 정할 일**: Expert 모드로 바꾸고 아래 양식으로 회의를 엽니다. 발언 순서와 이름을 정해 주면 역할이 섞이지 않습니다.
  ```
  회의 안건: P001 결말을 A/B 중 무엇으로 할지
  참석: 하린, 도윤, 준호 (서아는 불참)
  자료: (시놉시스 붙여 넣기)
  진행: 참석자 순서대로 [이름]을 붙여 의견과 근거를 말하고, 서로 반박한 뒤
        마지막에 결론 1개 / 남은 쟁점 / 대표가 결정할 것으로 정리해 줘
  ```
- **역할이 섞였을 때**: 답에 [이름]이 없거나, 한 직원이 남의 일까지 하면 `[이름]을 붙여서 담당별로 다시 정리해 줘`라고 합니다. 반복되면 새 대화를 엽니다.
- **결과물 옮기기**: 직원이 준 결과는 그대로 두지 말고 레포의 해당 파일(위 표)에 붙여 넣고 커밋합니다. 레포가 정본이고, Grok 대화는 초안입니다.
- **생성 기록**: Higgsfield 등 생성 툴에 프롬프트를 넣었다면 `03-production/generation-log.md`에 기록합니다(작성은 직원, 기록은 사람).

## 6. 지시문 고치는 규칙

1. 레포의 `studio/agents/<역할>.md`를 먼저 고칩니다.
2. Grok **Customize** 화면에서 해당 직원 지시문에 그대로 붙여 넣습니다.
3. 루트 `CHANGELOG.md` "변경"에 한 줄 적습니다. 바꾼 *이유*가 중요하면 `studio/decisions/`에 결정 문서를 씁니다.

## 7. 주의

- 비밀번호, API 키, 결제 정보는 **Grok 대화에 절대 붙여 넣지 않습니다.**
- 실존 인물의 얼굴·목소리·이름, 다른 작품의 캐릭터를 흉내 내라고 시키지 않습니다. 상업 이용 조건은 `studio/licenses.md`를 따릅니다.
