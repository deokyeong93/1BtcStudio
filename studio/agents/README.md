# 1BtcStudio 직원팀

1BtcStudio의 직원은 **Claude Code 서브에이전트**입니다. 대표는 `/1btcstudio` 스킬 하나로 직원팀을 움직입니다.

```
/1btcstudio P001 어떤 이야기로 갈지   → 직원끼리 회의해서 결론 확정, 회의록 기록
/1btcstudio 로그라인 써 줘            → 담당 직원(하린)이 써서 레포에 기록
/1btcstudio 다음                      → 단계표에서 다음 할 일을 골라 진행
```

- 대표는 회의에 들어가지 않습니다. **직원끼리 토론해 결론을 확정**하고 대표는 결과 보고만 받습니다.
- 대표 승인이 필요한 것은 **크레딧이 드는 생성 실행**과 **YouTube 공개**뿐입니다.
- 결과는 레포 파일에 바로 기록됩니다. 커밋은 대표가 요청할 때만 합니다.
- 스킬 정의: `.claude/skills/1btcstudio/SKILL.md` / 직원 정의: `.claude/agents/`

## Claude Code 실행 규칙

직원 서브에이전트는 매뉴얼(각 파일의 "## 지시문" 블록)을 따르되, 아래가 다르면 **이 규칙이 우선**합니다.

1. **파일을 쓰지 않는다.** 결과를 답으로 돌려주면 진행자(Claude Code 본체)가 레포에 기록한다.
2. **대표에게 묻지 않는다.** 대표는 참석하지 않는다. 모르는 정보는 "확인 필요"로 표시하고 가장 무난한 가정으로 진행한다.
3. 매뉴얼의 "유나(비서)에게 보고", "넘김 메모"는 **답 끝에 넘김 메모를 쓰는 것**으로 대신한다. 다른 직원을 직접 부르지 않는다.
4. 고를 것이 있으면(로그라인 3개, 시안 3개 등) 반드시 **추천 1개와 이유**를 붙인다. 추천안이 채택된다.
5. **회의 호출**이면 자기 담당 관점의 의견만 낸다. 결과물(대본, 프롬프트, 시안)은 만들지 않는다. 글자 수 제한은 호출 프롬프트를 따른다.
6. **업무 호출**이면 자기 담당 결과물만 만든다. 담당 밖 요청이 섞여 있으면 그 부분은 하지 않고 넘김 메모에 담당자를 적는다.

## 매뉴얼 고치는 법

1. 방향이 바뀌면 [studio-style.md](studio-style.md)를 먼저 고칩니다.
2. 해당 직원의 매뉴얼(`writer.md` 등)을 고칩니다. 서브에이전트는 매번 이 파일을 읽으므로 따로 다시 등록할 필요가 없습니다.
3. 루트 `CHANGELOG.md` "변경"에 한 줄 적습니다.
