# 1BtcStudio 직원팀

대표는 `/1btcstudio`로 다음 단계 하나만 진행합니다. 단계 스킬이 같은 세션에서 한 명씩 일하고, 결과를 레포 파일에 씁니다.

```
/1btcstudio 다음                         → 안 끝난 단계 하나
/1btcstudio-04step-prepare <보충>       → 0~4를 이어서. 판정·예산 종류만 고름. 생성은 안 함
/1btcstudio-0step-series                → 시리즈인지 새 이야기인지, 예산 종류, 음악·효과음은 선택지
/1btcstudio-1step-story                 → 로그라인·대본
/1btcstudio-5step-generate 120          → 숫자 한도 안에서 생성
```

- 대표는 0단계의 판정, 예산 종류, 음악·효과음만 고릅니다. 그 외는 추천안을 채택합니다.
- 대표 승인은 **숫자로 적은 크레딧 한도**와 **YouTube 공개**뿐입니다. 대본 검수와 프롬프트 검수는 생성 전에, 승인 없이 합니다.
- 커밋은 대표가 요청할 때만 합니다.
- 스킬: `.claude/skills/1btcstudio-0step-series`부터 `7step-release`. 라우터는 `.claude/skills/1btcstudio/SKILL.md`.

## 실행 규칙

매뉴얼의 "## 지시문" 블록을 따르되, 아래와 다르면 **이 규칙이 우선**합니다.

1. **단계 스킬이 파일을 쓴다.** 이미 내용이 있으면 지우지 말고 새 버전 섹션을 위에 추가한다.
2. **대표에게 묻지 않는다.** 예외는 0단계의 판정, 예산 종류, 음악·효과음이다. 이 셋은 매번 선택지로 묻고, 답이 없으면 넘어가지 않는다. 모르는 정보는 "확인 필요"로 적고, 그 외 고를 것은 추천안을 채택한다.
3. 한 단계에 사람이 둘 이상이면 **한 명씩 순서대로** 한다. 한 메시지에 병렬로 부르지 않는다. 서브에이전트를 쓰지 않는다.
4. 유나는 점수와 `통과`/`막힘`만 잠근다. 대본·프롬프트·제목을 고쳐 쓰지 않는다.
5. 크레딧이 드는 생성은 프롬프트 검수가 `통과`이고, 대표가 숫자를 입력한 뒤에만 한다.
6. 스킬은 두 작법 파일을 읽어 적용한다. 작법 전문을 스킬 안에 복사하지 않는다.

## 매뉴얼 고치는 법

1. 대사·연출이 바뀌면 `dialogue-style.md` 또는 `direction-style.md`를 먼저 고칩니다.
2. 해당 직원 매뉴얼을 고칩니다. 단계 스킬이 그 파일을 읽습니다.
3. 루트 `CHANGELOG.md` "변경"에 한 줄 적습니다.
