# 제작 가이드북: 주제 한 줄 → 영상 완성 (대표용)

다음 작품부터는 0단계부터 순서대로 부릅니다. 대표가 하는 일은 **단계 스킬, 결제 한 번, 결과 확인, 마무리 편집**입니다. 한 번에 다음 단계만 하려면 `/1btcstudio 다음`입니다.
툴 화면 사용법(ElevenLabs·Suno·CapCut·YouTube)은 [tool-guide.md](tool-guide.md)를 봅니다.

> 확인 기준일: **2026-10-04** (Higgsfield MCP로 직접 조회·생성해 봄). 요금·단가는 자주 바뀌므로 스킬이 생성 전에 다시 조회합니다.
> 비밀번호·카드 정보는 어디에도 적지 않습니다.

## 1. 생성 전 (0~4단계, 크레딧 0)

```
/1btcstudio-0step-series 회사 면접관이 사실 AI였다면
```

0부터 4까지 한 번에 가려면 보충만 적습니다. 판정, 예산 종류, 음악·효과음만 고르고, 생성 전에 멈춥니다.

```
/1btcstudio-04step-prepare 회사 면접관이 사실 AI였다면, 3분
```

한 단계씩 가려면 `/1btcstudio 다음`을 반복합니다.

- 주제 한 줄이면 됩니다.
- 새 작품 폴더는 1단계가 `scripts/new-project.sh`로 만듭니다. GitHub 이슈는 만들지 않습니다.
- 0단계의 판정, 예산 종류, 음악·효과음만 대표가 고릅니다. 그 외는 추천안을 채택합니다.
- 캐스팅·의상은 [casting-style.md](agents/casting-style.md)를 따른다. 생성 프롬프트에 배우 이름과 "actor-level looks"를 넣지 않는다.
- 4단계가 `통과`로 끝나면 다음 입력은 `/1btcstudio-5step-generate <예상 크레딧 + 여유>`입니다.

**마음에 안 들면** 생성 전에 말로 고칩니다. 예: `<이름> 외모를 더 차분하게 바꿔 줘`, `씬 3 빼 줘`. 사진을 보여 줘도 됩니다. 실존 인물 사진은 분위기만 참고하고 얼굴은 닮게 만들지 않습니다.

## 3. 결제와 연결 (처음 한 번)

1. higgsfield.ai → Pricing → **Plus, Monthly** 결제. (Claude Code에 "힉스필드 요금제 보여 줘"라고 하면 결제 링크가 나옵니다.)
2. Claude Code에서 `/mcp` → `higgsfield`가 **connected**인지 봅니다.
3. 아니면 "힉스필드 로그인해 줘" → 나온 주소를 브라우저에서 열고 로그인·허용 → 브라우저에 "연결할 수 없음"이 떠도 정상입니다. 주소창의 `http://localhost:…/callback?code=…`를 통째로 복사해 Claude Code에 붙여 넣습니다.
4. "힉스필드 잔액 알려 줘"로 확인합니다.
5. [tools.md](tools.md)와 [budget.md](budget.md) "월 구독료"에 한 줄씩 적게 합니다: "힉스필드 Plus 결제했어, 장부에 적어 줘".

## 4. 생성 (`/1btcstudio-5step-generate <한도>`)

`prompt-review.md`가 `통과`이고 숫자가 있을 때만 생성합니다. 싼 시험은 `체험 <한도>`입니다. 이것도 통과 후입니다.

### 1차: 얼굴 + 테스트 샷
```
/1btcstudio-5step-generate 120
```
1. 서아의 기준 얼굴 생성 → 서아 검수 → 통과한 얼굴로 **캐릭터 Element 등록**(이름 = 레포 id). Element는 사진 1장으로 바로 만들어지고 이미지·영상 모델 모두에서 같은 얼굴을 씁니다.
2. 방 이미지 → 테스트 샷의 첫 장면 이미지 → `credit-estimate.md` 순서의 테스트 샷 영상 → 서아 검수. 체험이면 샷 1개.
3. 보고가 오면 **대표가 테스트 샷을 직접 재생해 봅니다.** 서아는 1초 간격 정지 화면만 보므로 움직임의 어색함은 대표 눈이 정확합니다.
   - 얼굴이 마음에 안 들면: `<이름> 얼굴 다시, 더 성숙하게, 한도 5`
   - 실존 배우가 떠오르면: `<이름>이 ○○ 닮았어, 다시` (서아는 대표가 본 참고 사진을 볼 수 없습니다)

### 2차: 나머지 전부
```
/1btcstudio-5step-generate 400
```
- 이미 approved된 샷과 등록된 캐릭터는 건너뜁니다.
- 멈추면 보고의 "다음"을 그대로 다시 넣습니다.
- 멈추는 조건: 한도 도달, 잔액 부족, 오류 3번 연속, 로그인 만료, 같은 샷 3번 연속 redo(대안을 보고에 적음)

### 결과물 위치
| 무엇 | 어디 | git |
|---|---|---|
| 이미지·영상·음성 원본 | `projects/<작품>/media/` | 안 올라감 → 대표가 클라우드에 백업 |
| 프롬프트·시도 기록, 생성 일지 | `03-production/prompts/`, `generation-log.md` | 올라감 |
| 크레딧 합계 | `studio/budget.md` | 올라감 |
| 샷 상태 | `02-preproduction/shotlist.csv` | 올라감 |

## 5. 소리·가편집 (`/1btcstudio-6step-post`)

숫자가 없으면 원고와 편집 노트만 쓰고 멈춥니다. 음성은 검수를 통과한 대사를 그대로 읽습니다. 고른 목소리 id는 작품 `base.md`에 잠급니다.

```
/1btcstudio-6step-post 20
```
1. **목소리**: `base.md`에 id가 있으면 그것만 씁니다. 없으면 대사와 같은 언어의 프리셋을 하나 고르고 잠급니다. 로봇처럼 들리면 id를 바꾸거나 참고 음성을 잠급니다. 같은 id로 문장만 바꿔 다시 뽑지 않습니다.
2. **내레이션 생성**: 씬 단위로 만들어 `media/`에 저장합니다.
3. **가편집본**: ffmpeg로 approved 샷을 편집 노트 순서대로 잇고 음성을 얹어 `media/P00X_edit_v1.mp4`를 만듭니다. 자막 파일(`.srt`)은 `04-post/subtitles/`에 저장합니다.
4. 채팅 화면·손글씨처럼 그래픽이 필요한 컷은 검은 화면 자리표시로 두고 목록을 보고합니다.

제목·썸네일·설명은 `/1btcstudio-7step-release`입니다. 업로드는 하지 않습니다.

## 8. 2026-10-04 체험에서 배운 것

- **Basic 요금제는 Kling 3.0 생성이 막힙니다**(단가 조회만 됨). 실제 제작은 Plus로 합니다.
- **얼굴을 넣은 장면 이미지는 `gpt_image_2_5`가 맞습니다.** `soul_2`에 얼굴 사진을 참고로 넣으면 증명사진 구도를 그대로 따라갑니다. 프롬프트 첫 줄에 "참고 이미지는 얼굴만, 구도는 따르지 말 것"을 적습니다.
- **프롬프트 끝에 "no ○○"를 길게 나열하면 금지한 것이 오히려 그려집니다.** 원하는 것을 긍정문으로 씁니다.
- **점·소품의 좌우는 자주 뒤집힙니다.** 콧등처럼 좌우가 없는 위치가 안전합니다.
- **영상은 첫 장면 이미지를 꼭 넣습니다.** 얼굴 참고만 넣으면 카메라 높이·방·소품이 바뀝니다.
- **소리가 필요 없는 샷은 소리를 끕니다.** Kling 3.0 pro 10초가 25에서 17.5로 줄어듭니다.
- 이미지는 장당 0.12~0.5라 아끼지 않아도 됩니다. 크레딧은 영상에서 나갑니다.
