# 제작 가이드북: 주제 → 기획 → 크레딧 → Higgsfield 영상 (대표용)

대표가 하는 일은 **명령 세 번과 결제 한 번**입니다. 나머지는 직원팀(Claude Code)이 합니다.
소리·편집·공개처럼 대표가 직접 만지는 툴은 [tool-guide.md](tool-guide.md)를 봅니다.

> 확인 기준일: **2026-10-04** (Higgsfield MCP로 직접 조회). 요금·단가는 자주 바뀌니 스텝 1이 끝날 때 다시 조회합니다(스킬이 자동으로 함).
> 비밀번호·카드 정보는 어디에도 적지 않습니다.

---

## 0. 전체 흐름

| 스텝 | 대표 입력 | 직원팀이 하는 일 | 크레딧 |
|---|---|---|---|
| 1 기획 | `/1btcstudio-1step 기획 <주제>` | 새 작품 폴더 → 이야기 회의 → 로그라인·시놉시스·대본·캐릭터 → 화면·주인공 회의 → 외모 시트·샷리스트·프롬프트 → **예상 크레딧** 보고 | 0 |
| (결제) | Higgsfield 결제, `/mcp` 연결 확인 | | |
| 2 생성 | `/1btcstudio-1step 생성 <한도>` | 기준 얼굴 → Soul ID 학습 → 방·첫 장면 이미지 → 샷 영상 → 서아 검수 → 재생성 → 기록 | 한도 안에서만 |
| 3 소리·편집 | `/1btcstudio-1step` | 소리·편집 회의 → 준호가 내레이션 원고·효과음·음악·편집 노트·자막·메타데이터 | 0 |
| (대표 직접) | | ElevenLabs·Suno·CapCut·YouTube → [tool-guide.md](tool-guide.md) 3~6장 | 툴별 |

- 스텝 1은 주제만 주면 묻지 않고 끝까지 갑니다. 방향은 직원 회의에서 정하고 회의록이 `meetings/`에 남습니다.
- 스텝 2의 **숫자가 대표의 크레딧 승인**입니다. 그 숫자를 넘기 전에 멈춥니다.
- 하나씩 보고 싶으면 `/1btcstudio 다음`(다음 할 일 하나만) 또는 `/1btcstudio <요청>`(업무 하나·회의 하나)을 씁니다.

## 1. 스텝 1: 기획 (크레딧 0)

```
/1btcstudio-1step 기획 회사 면접관이 사실 AI였다면
```
- 주제는 한 줄이면 됩니다. 길이·분위기·화면 형식을 정해 두고 싶으면 같이 적습니다(예: `기획 …, 3분, CCTV 화면`).
- 새 작품은 `projects/P00X-<slug>/`로 만들어지고 루트 `README.md` 작품 표 맨 위에 올라갑니다. 이후 명령은 이 작품을 대상으로 합니다.
- 끝나면 아래 형식으로 한 번만 보고합니다. "다음 입력"을 그대로 쓰면 됩니다.
```
결과: 1~2단계 완료, 샷 16개
사용 크레딧: 0
결과물: 01-development/…, 02-preproduction/…, 03-production/credit-estimate.md
다음 입력: /1btcstudio-1step 생성 700
```
- 이어서 하던 작품을 계속할 때는 주제 없이 `/1btcstudio-1step`.

## 2. 크레딧 계산과 요금제

### 단가 (2026-10-04 조회)
| 모델(MCP 이름) | 용도 | 단가 |
|---|---|---|
| Soul 2 (`soul_2`) | 기준 얼굴, 학습 사진, 방·첫 장면 이미지 | 이미지 1장 **0.12** (화면에는 1로 표시) |
| Soul ID 학습 | 캐릭터 얼굴 고정 | 약 17~30 (요금제 안내 문구 추정, **확인 필요**) |
| Kling 3.0 std (`kling3_0`, mode std) | 샷 영상 | 5초 10 / 8초 16 |
| Kling 3.0 pro (`kling3_0`, mode pro) | 샷 영상 (도윤 기본안) | 5초 12.5 / 8초 약 20 |
| Seedance 2.0 720p (`seedance_2_0`) | 대안 | 5초 22.5 |
| Seedance 2.5 1080p (`seedance_2_5`) | 어려운 샷 대안 | 5초 60 |
| Seedance 2.0 mini 480p (`seedance_2_0_mini`) | 구도만 확인할 때 | 5초 2.5 |

### 예: P001 (샷 16개, 8초 7개 + 5초 9개, 샷마다 2~3회 시도)
| 항목 | 크레딧 |
|---|---|
| 이미지 약 120장 (얼굴·학습 사진·방·첫 장면) | 약 15 |
| Soul ID 학습 2명 | 약 35~60 |
| 샷 영상 (pro / std) | 약 565 / 450 |
| **합계 (pro / std)** | **약 615~640 / 500~525** |

### 요금제 (2026-10-04 조회)
| 상품 | 크레딧 | 가격 |
|---|---|---|
| Plus 월간 | 월 1,000 | $49 |
| Plus 연간 | 월 1,000 | $29/월 (1년 결제) |
| Ultra 월간 / 연간 | 월 3,000 | $99 / $70/월 |
| 추가 크레딧 500 / 1,000 / 2,000 | 1회 | $26 / $49 / $95 (**90일 뒤 소멸**) |

**추천: Plus 월간 1개월.** 작품 1편이 약 500~650이라 1,000 안에 재생성 여유까지 들어갑니다. 계속 만들기로 정하기 전에는 연간을 고르지 않습니다. 모자라면 추가 크레딧 500을 삽니다. 요금제 크레딧이 다음 달로 넘어가는지는 확인 필요라, 결제한 달 안에 다 쓴다고 봅니다.

## 3. 결제

1. higgsfield.ai 로그인 → Pricing → **Plus, Monthly** → 결제
   (Claude Code에 "힉스필드 요금제 보여 줘"라고 하면 결제 링크가 나옵니다.)
2. 결제 화면에서 자동 갱신 해제 위치를 봐 둡니다(8장).
3. [tools.md](tools.md)와 [budget.md](budget.md) "월 구독료"에 한 줄씩 적습니다.

---

## 4. Higgsfield MCP 연결

`.mcp.json`에 이미 등록되어 있습니다. 로그인만 확인합니다.
1. Claude Code에서 `/mcp` → `higgsfield`가 **connected**면 끝.
2. 아니면 Claude에게 "힉스필드 로그인해 줘" → 나온 주소를 브라우저에서 열고 로그인·허용.
3. 브라우저에 "연결할 수 없음"이 떠도 정상입니다. 주소창의 `http://localhost:…/callback?code=…` 주소를 통째로 복사해 Claude Code에 붙여 넣습니다.
4. "힉스필드 잔액 알려 줘"로 크레딧이 보이면 준비 끝.

새 컴퓨터라 `/mcp`에 higgsfield가 아예 없으면 터미널에서 한 번:
```
! claude mcp add --transport http --scope project higgsfield https://mcp.higgsfield.ai/mcp
```

## 5. 스텝 2: 생성

### 1차: 캐릭터 + 테스트 샷
```
/1btcstudio-1step 생성 150
```
- 기준 얼굴 → 학습 사진 → Soul ID 학습 → 방·첫 장면 이미지 → 테스트 샷 2개(도윤이 정한 순서)까지 하고 한도에서 멈춥니다.
- **대표가 테스트 샷을 직접 재생해 봅니다.** 서아는 1초 간격 정지 화면만 보므로 움직임이 어색한 건 못 잡습니다.
- 고칠 게 있으면 말로 합니다: `S05 인사가 너무 빨라. 도윤 재생성 지시 받아서 다시, 한도 20`
- std와 pro 비교: `S05를 kling3_0 std로도 뽑아서 비교하게 해 줘, 한도 15` → 차이가 작으면 나머지를 std로 갑니다(약 100 절약).

### 2차: 나머지 전부
```
/1btcstudio-1step 생성 500
```
- 남은 크레딧에서 여유 100 정도를 뺀 숫자를 넣습니다.
- 중간에 멈추면 보고의 "다음 입력"을 그대로 다시 넣습니다. 이미 approved된 샷과 학습된 Soul ID는 건너뜁니다.
- 멈추는 조건: 한도 도달, 잔액 부족, MCP 오류 3번 연속, 로그인 만료, 같은 샷 3번 연속 redo, 실존 인물 닮음 3번

### 결과물 위치
| 무엇 | 어디 | git |
|---|---|---|
| 이미지·영상 원본 | `projects/<작품>/media/` (`P001_shot_S05_v1.mp4` 식) | 안 올라감 → 대표가 클라우드에 백업 |
| 검수용 프레임 | `media/frames/<파일명>/` | 안 올라감 |
| 시도 기록·생성 일지 | `03-production/prompts/S0X.md`, `generation-log.md` | 올라감 |
| 크레딧 합계 | `studio/budget.md` | 올라감 |
| 샷 상태 | `02-preproduction/shotlist.csv` (approved) | 올라감 |

Higgsfield 웹사이트의 내 생성물에도 같은 결과가 남습니다.

## 7. 크레딧 아끼는 법 (2026-10-04 체험에서 배운 것)

체험: Basic 80크레딧으로 기준 얼굴 6장, 방 R1, S05 테스트 영상 1개를 만들어 **3.34크레딧** 썼습니다. 기록은 [P001 generation-log.md](../projects/P001-pilot/03-production/generation-log.md)에 있습니다.

- **Soul ID 없이 프롬프트만으로는 얼굴이 시트대로 안 나옵니다.** 3번 고쳐도 점 위치가 뒤집히고, 안경테·체형·머리 묶는 높이가 틀렸습니다. 본편에서는 Soul ID 학습을 건너뛰지 않습니다.
- **"아닌 것"을 적으면 조금 나아집니다**: `not obese`, `not square frames`, `no backpack`. 점 좌우는 `appearing on the left side of the image`처럼 화면 기준으로도 씁니다.
- **영상은 첫 장면 이미지를 꼭 넣습니다.** 얼굴 참고 이미지만 넣었더니 카메라 높이·방 배치·소품(숄더백 → 백팩)이 바뀌었습니다.
- **구도 확인은 싼 모델로**: 비싼 모델로 뽑기 전에 `seedance_2_0_mini` 480p(5초 2.5)로 움직임만 봅니다.
- **다시 뽑을 때는 한 가지만 바꿉니다.** 여러 개를 바꾸면 무엇이 효과였는지 모릅니다.
- 이미지는 장당 0.12라 아끼지 않아도 됩니다. 크레딧은 영상에서 나갑니다.
