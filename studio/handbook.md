# 스튜디오 운영 규칙 (Handbook)

이 문서는 1BtcStudio가 일하는 방식입니다. 규칙이 바뀌면 이 문서를 고치고 루트 `CHANGELOG.md`에 "변경"으로 남깁니다.

## 1. 작업 흐름

```
이슈 만들기 → 보드에서 In progress → 작업·기록 → (Review) → CHANGELOG 반영 → 이슈 닫기(Done)
```

- **모든 작업은 이슈에서 시작합니다.** 이슈가 없는 작업은 기록이 남지 않습니다. 떠오른 생각은 `type:idea` 이슈로 적어 둡니다.
- 프로젝트 보드 칸의 의미:
  - **Backlog**: 할 일
  - **In progress**: 지금 하는 일 (한 번에 1~2개만)
  - **Review**: 결과물을 하루 뒤에 다시 보고 판단할 것
  - **Done**: 끝난 일
- 작품은 5단계 순서대로 진행합니다. 앞 단계 이슈를 닫아야 다음 단계를 시작합니다.

| 단계 | 라벨 | 이 단계가 끝났다는 기준 |
|---|---|---|
| 0. 스튜디오 | `stage:0-studio` | 툴 가입·요금제·라이선스 확인 완료 |
| 1. 기획 | `stage:1-development` | 대본과 러닝타임 확정 |
| 2. 프리프로덕션 | `stage:2-preproduction` | 샷 리스트와 샷별 프롬프트 초안 완성, 캐릭터 Soul ID 등록 |
| 3. 프로덕션 | `stage:3-production` | `shotlist.csv`의 모든 샷이 `approved` |
| 4. 포스트 | `stage:4-post` | 최종본 내보내기 완료 |
| 5. 배포 | `stage:5-distribution` | YouTube 공개, 회고 작성 |

### AI 팀과 일하는 방식

```
대표 ──/1btcstudio <안건·요청>──▶ Claude Code (진행자·레포 관리자)
                                   ├─ 회의: 직원 서브에이전트 2라운드 토론 → 유나(비서)가 결론 확정
                                   └─ 업무: 담당 직원 1명이 결과물 작성
                                   ▼
                              레포에 기록 (회의록·작품 파일) ──▶ 대표에게 짧은 보고 ──▶ 커밋(대표 요청 시)
```

| 누구 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 대표 | `/1btcstudio`로 일 시키기, 크레딧 생성·YouTube 공개 승인 | 회의 참석 (직원끼리 결론을 냄) |
| 직원 서브에이전트 (하린·도윤·서아·준호·유나) | 회의 의견, 결론 확정, 대본·프롬프트·시안 같은 **결과물 제작** | 레포에 직접 쓰기, 남의 담당 일 |
| Claude Code 본체 | 회의 진행, 담당자 배정, 결과를 템플릿 형식으로 레포에 기록, 형식·일관성 검사 | 작품 내용에 대한 의견, 직원 발언 수정, 요청 없이 커밋 |

- **레포가 정본**입니다. 회의록과 작품 파일에 들어간 내용만 공식 기록입니다.
- 직원 구성·실행 규칙은 [studio/agents/](agents/README.md), 스킬 정의는 `.claude/skills/1btcstudio/SKILL.md`를 봅니다.

## 2. 브랜치·커밋 규칙

- 1인 운영이므로 **`main` 브랜치에 바로 커밋**합니다.
- 결과가 불확실한 큰 실험(예: 대본을 통째로 다시 쓰기)만 브랜치를 만듭니다. 이름은 `p001/script-rewrite` 형식입니다.
- 커밋 메시지는 한국어로 쓰고, **반드시 이슈 번호를 붙입니다.**
  - 형식: `<작품번호> <무엇을> <어떻게> #<이슈번호>`
  - 예: `P001 샷 S03 프롬프트 수정 #12`, `스튜디오 Suno 요금제 기록 #4`
- 커밋 메시지에 `closes #12`를 쓰면 push할 때 이슈가 자동으로 닫힙니다. CHANGELOG를 반영한 다음에만 사용하세요.

## 3. 파일 네이밍

### git에 올리는 텍스트 파일
- 영문 소문자와 하이픈(`-`)만 씁니다. 예: `edit-notes.md`, `S03.md`
- 작품 폴더: `projects/P001-<slug>/` (slug는 영문 소문자와 하이픈)
- 결정 문서: `studio/decisions/0001-제목.md` (번호는 4자리, 1씩 증가)

### 미디어 원본 파일 (외부 저장소에 보관)
```
P001_<종류>_<샷ID 또는 이름>_v<번호>.<확장자>
```
| 종류 | 의미 | 예시 |
|---|---|---|
| `shot` | 생성된 샷 영상 | `P001_shot_S03_v4.mp4` |
| `char` | 캐릭터 시트 이미지 | `P001_char_mina_v2.png` |
| `voice` | 대사·내레이션 음성 | `P001_voice_S03-mina_v1.wav` |
| `lipsync` | 립싱크된 샷 | `P001_lipsync_S03_v1.mp4` |
| `music` | 배경음악 | `P001_music_main_v2.mp3` |
| `sfx` | 효과음 | `P001_sfx_door_v1.wav` |
| `edit` | 편집본 | `P001_edit_v2.mp4` |
| `final` | 최종본 | `P001_final_v1.mp4` |
| `thumb` | 썸네일 | `P001_thumb_v3.png` |

- 버전 번호는 **덮어쓰지 않고 항상 올립니다.** v3이 마음에 안 들어도 지우지 말고 v4를 만드세요.
- 작품 `CHANGELOG.md`의 버전(`편집본 v2`)은 원본 파일 버전(`P001_edit_v2.mp4`)과 1:1로 대응합니다.

## 4. 미디어 파일 정책

- **영상·음원·이미지 원본은 git에 커밋하지 않습니다.** 파일이 크고 git은 큰 파일 관리에 적합하지 않습니다. `.gitignore`가 자동으로 막아 줍니다.
- 원본은 외부 저장소(클라우드 폴더)에 둡니다. 어디에 둘지는 M0 결정 이슈에서 정하고 `studio/decisions/`에 기록합니다.
- 외부 저장소의 폴더 구조는 레포와 같게 맞춥니다: `1BtcStudio/P001-pilot/03-production/...`
- 각 작품 `README.md`의 "원본 미디어 링크" 표에 **링크만** 적습니다.
- git으로 관리하는 것: 프롬프트, 대본, 로그, 문서, 자막(.srt), 샷 리스트(.csv)

## 5. 기록 규칙

### 기록은 세 곳에 나눠서 합니다 (같은 내용을 두 곳에 쓰지 않고 링크로 연결)

| 기록 | 질문 | 예 |
|---|---|---|
| `generation-log.md` | **어떻게** 했나? (작업 일지, 세부 과정) | "S03 v1~v4 생성, v2는 손가락 깨짐으로 폐기" |
| `studio/decisions/` | **왜** 그렇게 정했나? (이유) | "립싱크 툴을 sync.so로 바꾼 이유" |
| `CHANGELOG.md` | **무엇이** 바뀌었나? (결과 요약) | "편집본 v2: S03 교체 (#12, 결정 0004)" |

### 규칙
1. 모든 작업은 이슈에서 시작하고, 커밋에 이슈 번호를 넣습니다.
2. **생성 작업은 한 번도 빠짐없이** `03-production/generation-log.md`에 기록합니다. 날짜, 툴, 모델, 프롬프트(또는 프롬프트 파일 링크), 사용 크레딧, 결과(채택/폐기와 이유)를 적습니다. 실패한 생성도 기록합니다. 실패 기록이 다음 작품의 시간을 아껴 줍니다.
3. 크레딧을 쓰면 `studio/budget.md`의 "크레딧 사용 내역"에도 합계를 남깁니다.
4. 선택지가 2개 이상이고 나중에 "왜 이렇게 했지?"라는 질문이 나올 것 같은 일은 `type:decision` 이슈를 만들고 `studio/decisions/`에 문서로 남깁니다.
5. **단계가 끝나면** 해당 이슈에 회고 코멘트를 남깁니다:
   ```
   ### 회고
   - 잘된 점:
   - 문제:
   - 다음에 바꿀 점:
   ```
6. **작품이 끝나면** `projects/P00X-.../retrospective.md`를 작성합니다.
7. **이슈를 닫기 전에** CHANGELOG(루트 또는 작품)에 반영했는지 확인합니다. 모든 이슈 템플릿의 마지막 체크박스가 이것입니다.

## 6. 계정·보안
- 비밀번호, API 키, 결제 정보는 **절대 레포에 적지 않습니다.** `tools.md`에는 "어떤 이메일로 가입했는지" 정도만 적습니다.

## 용어 풀이 (영상 제작 비전문가용)

| 용어 | 뜻 |
|---|---|
| 로그라인 | 작품을 한 문장으로 요약한 것. "누가, 무엇을 원하는데, 무엇이 방해한다" |
| 시놉시스 | 줄거리 요약 (반 페이지 정도) |
| 샷 (shot) | 카메라가 끊기지 않고 찍은 한 덩어리. AI 영상은 샷 단위로 생성합니다 |
| 씬 (scene) | 같은 장소·시간에서 일어나는 샷들의 묶음 |
| 샷 리스트 | 모든 샷의 목록 (번호, 길이, 내용, 카메라 움직임) |
| 콘티 / 스토리보드 | 샷을 그림이나 설명으로 순서대로 정리한 것 |
| 캐릭터 시트 | 캐릭터의 얼굴·옷·체형을 여러 각도에서 보여 주는 기준 이미지 |
| Soul ID | Higgsfield에서 캐릭터 얼굴을 등록해 여러 샷에서 같은 얼굴로 나오게 하는 기능 |
| 립싱크 | 음성에 맞춰 입 모양을 움직이게 하는 작업 |
| 컷 편집 | 샷들을 순서대로 붙이고 길이를 다듬는 작업 |
| 색보정 | 샷마다 다른 색감과 밝기를 하나로 맞추는 작업 |
| 믹싱 | 대사·음악·효과음의 볼륨 균형을 맞추는 작업 |
| 러닝타임 | 작품의 총 길이 |
